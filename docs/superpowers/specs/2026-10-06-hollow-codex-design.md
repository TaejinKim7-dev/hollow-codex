# 빈 경전 (Hollow Codex) — 게임 설계 스펙

작성: 2026-10-06 · 상태: 사용자 검토 대기

## 0. 한 줄 요약

미덕이 제도가 되어 굳어 버린 대륙에서, 이방인이 사람들과 대화하며 모은 지식으로 여덟 미덕의 본래 뜻을 되찾고, 마지막에 비어 있는 경전에 자기 답을 써 넣는 **지식 기반 탐험 RPG**. 웹(PC + 모바일 터치), 한국어 우선, 6~10시간.

## 2. 원작과의 경계 (IP)

공개 독립 게임이므로 **개념은 계승하되 이름과 글은 새로 만든다**.

### 2.1 의식적으로 계승하는 것 (아이디어 수준)
- 여덟 미덕(정직·연민·용맹·정의·희생·명예·영성·겸손)과 그 바탕인 세 원리(진실·사랑·용기)의 구조. 일반 단어이며, 원작에 대한 오마주로 의도적으로 유지한다.
- 악당 없이 스스로를 시험하는 이야기 구도, 키워드로 묻는 대화, 행실에 따라 동료가 떠나는 규칙, 둥글게 선 돌의 관문으로 온 이방인, 마지막에 미덕에 관한 답을 요구하는 엔딩.

### 2.2 쓰지 않는 것 (금지 목록)
- 상표·고유명사: Ultima/울티마, Britannia/브리타니아, Sosaria, Lord British/로드 브리티시, Avatar/아바타(칭호로서), Moongate/문게이트, Trammel/트래멀, Felucca/펠루카, Codex of Ultimate Wisdom(및 "궁극적 지혜의 경전" 같은 직역), Stygian Abyss/심연(고유명으로서), Hawkwind, Mondain, Minax, Exodus.
- 원작 지명: Britain, Yew, Minoc, Trinsic, Jhelom, Skara Brae, Moonglow, Magincia, Vesper, Cove, Paws, Buccaneer's Den, Serpent's Hold, Empath Abbey, Lycaeum 및 한글 음역.
- 원작 만트라(AHM, MU, RA, BEH, CAH, SUMM, OM, LUM)와 룬·돌·종·책·초 같은 원작 유물 체계의 이름.
- 원작 문장: 1985년 매뉴얼(*History of Britannia*) 본문, `origin.txt`에 실린 경전 질문, 원작 대사와 그 번역(기존 `ultima` 저장소의 한국어 번역 포함). 원곡 음악과 그 편곡.
- 참고 자료(`u4-alt-manual.pdf`, `origin.txt`)는 어느 저장소에도 커밋하지 않는다. 구조 분석 결과는 우리 말로 다시 써서만 남긴다.

### 2.3 강제 방법
- 콘텐츠 검사기(§7.4)가 `content/`와 문자열 표 전체에서 금지 목록(영문 대소문자 무시, 한글 음역 포함)을 찾으면 빌드를 실패시킨다. 목록은 `content/ip-denylist.yaml` 한 곳에 둔다.

### 2.4 이름 확인
- 2026-10-06 일반 웹 검색: "Hollow Codex"라는 제목의 게임은 찾지 못했다. *Eternal Strands*의 게임 내 도감 항목 이름("Glintwood Hollow Codex")만 겹친다. 정식 상표 검색은 아니므로 공개(M6) 전에 다시 확인한다.

### 2.5 닮은 점에 대한 기록
- "미덕이 법으로 왜곡된 세계"는 Ultima V가 악당(통치자)을 통해 다룬 주제와 닮았다. 이 게임은 악당 없이 **제도 자체의 경화**를 다루는 것으로 구별한다.

## 3. 세계와 이야기

### 3.1 세계
- 대륙 이름: **알마(Alma)**. 여덟 마을이 각자 한 미덕의 교단 본거지다.
- 과거: 300년 전, 열석(둥글게 선 돌) 사이로 한 순례자가 와서 여덟 미덕을 몸소 보이고 떠났다. 순례자가 남긴 경전은 **비어 있었다** — "답은 각자 써야 한다"는 뜻이었다.
- 빈 책을 두려워한 여덟 교단은 각자 **주석**을 써 넣었고, 300년 동안 주석은 법이 되었다. 원래의 빈 경전은 봉인된 서고에 잠들어 있다.
- 현재: 아무도 악하지 않지만, 모두 선의로 서로를 옥죈다.

### 3.2 여덟 마을과 굳은 형태

| 미덕 | 굳은 형태 (마을의 문제) | 원리 |
|---|---|---|
| 정직 | 의무 고백과 상호 감시 | 진실 |
| 연민 | 자선을 위해 가난을 유지하는 위계 | 사랑 |
| 용맹 | 후퇴 금지, 무모한 결투 | 용기 |
| 정의 | 조문 맹종, 가혹한 형벌 | 진실·사랑 |
| 희생 | 순교 경쟁, 자기 소멸 강요 | 사랑·용기 |
| 명예 | 체면과 가문 서열 | 진실·용기 |
| 영성 | 형식뿐인 의식, 명상 면허제 | 진실·사랑·용기 |
| 겸손 | 침묵과 자기 이름 금지 | (세 원리의 부재를 깨닫는 자리) |

마을 이름은 금지 목록과 겹치지 않게 콘텐츠 작업에서 짓는다. M1의 정직 마을은 **칼라스(Kalas)**로 정한다.

### 3.3 흐름
1. **도입**: 열석을 지키는 늙은 문지기가 플레이어를 부른다(왕의 소환이 아님). 플레이어의 호칭은 처음엔 "이방인".
2. **마을마다**: 옛 편지, 순례자의 흔적, 이단자, 아이들 노래 같은 조각을 모아 그 미덕의 본래 뜻을 재구성하고(추론 페이지), 이해로 그 마을의 위기를 푼다.
3. **동료**: 마을마다 한 명이 그 마을의 굳은 믿음을 지닌 채 합류하고, 그 마을이 풀리면 동료의 이야기도 풀린다.
4. **이동**: 열석 고리들의 이름과 노래를 알아내면 고리 사이 순간이동이 열린다.
5. **엔딩**: 봉인된 서고에서 빈 경전을 펼친다. 경전이 질문하는 대신, 플레이어가 수첩에서 고른 여덟 답을 직접 써 넣는다. 마지막 장 "세 원리를 아우르는 하나"에 무엇을 쓰느냐에 따라 마을들의 에필로그가 달라진다.

## 4. 핵심 시스템

### 4.1 수첩 = 플레이어의 경전 (핵심)
- **단서(fact)**: 대화·읽기·관찰로 얻는 원자 단위 사실. 종류: 사람, 장소, 단어, 노래, 뜻 조각. 각 단서는 고유 id를 가진다.
- **키워드 대화**: 수첩의 단어는 누구에게나 물어볼 수 있다(칩 UI). NPC 응답이 새 단서를 줄 수 있다.
- **추론 페이지**: 마을마다 "이 미덕의 본래 뜻" 문장에 빈칸이 있다. 수첩의 단어로 채운다. **빈칸 3개가 모두 맞으면 확정되고, 그 전에는 몇 개가 맞았는지 알려 주지 않는다**(Golden Idol·Obra Dinn 방식, 찍기 방지).
- **소문 지도**: 아직 풀지 못한 연결을 "?" 노드로 보여 준다. 다음 행선지를 스스로 찾게 한다.

### 4.2 미덕 = 이해 + 행실
- **이해**: 추론 페이지 확정으로 얻는다. 반복 노가다 없음.
- **행실**: 숨은 기록. 거짓말, 악하지 않은 존재 살해, 도둑질, 동료 유기 등 행동 이벤트가 미덕별로 쌓인다.
- 성소 명상은 행실을 숫자 대신 말로 비춰 준다.

### 4.3 성장 = 깨달음
- 레벨·경험치 없음. 확정한 미덕마다 능력 하나가 열린다(예: 정직 → 대화 속 거짓 표시, 용맹 → 전투 버티기, 연민 → 설득해 물리기). 장비는 보조.

### 4.4 마을 위기
- 마을마다 위기 1개, 아는 것에 따라 풀이 2~3갈래. 고른 풀이가 엔딩 에필로그에 반영된다.

### 4.5 전투
- 작은 격자(예: 9×9) 턴제. 플레이어 + 동료 최대 3명. 적의 다음 행동을 미리 보여 준다.
- 고정 조우 전체 약 20회 + 선택 조우 소수.
- 행동: 공격, 방어, 밀어내기(퇴각시키기), 설득(조건부), 도주.
- 수첩의 **생물 도감**이 "이 존재는 정말 악한가"를 알려 준다. 악하지 않은 존재를 죽이면 행실에 기록된다.
- 무작위성은 최소화하고, 결과는 예고된 정보로 예측할 수 있게 한다.

### 4.6 동료
- 8명(마을당 1명), 동행 최대 3명. 행실이 그 동료의 미덕과 크게 어긋나면 떠나고, 조건을 채우면 돌아온다.

### 4.7 탐험
- 타일 지도, 지형별 이동 비용. 낮·밤에 따라 NPC 일과가 달라진다("누가 언제 어디에"도 지식). 열석 고리 순간이동.

### 4.8 편의
- 자동 저장 + 슬롯 + Google Drive 선택 동기화. 터치: 누르면 길찾기 이동, 칩 대화. 문자열 표 분리(한국어 우선, 영어는 M6 선택).

## 5. 그래픽
- 16×16 타일, 정수 배율 렌더링. 팔레트는 한 벌로 통일해 출처가 다른 타일도 어울리게 한다(필요하면 팔레트 재매핑).
- 출처 우선순위: CC0 → CC-BY → CC-BY-SA 타일셋, 그다음 직접 제작. 비상업(NC)·출처 불명 자산은 쓰지 않는다.
- 한글 글꼴: Neo둥근모(OFL).

## 6. 음악과 효과음 — 공개 자료 + 울티마 풍

### 6.1 "울티마 풍"의 정의
- 사각파·삼각파·잡음으로 된 3~4성부 칩 사운드.
- 중세·르네상스·바로크풍 선율.
- 장소마다 고유 테마(들판, 마을별, 성, 던전, 성소, 전투, 바다), 짧게 반복되는 곡.

### 6.2 방식
- 곡은 악보 데이터(MIDI)로 보관하고, 우리 칩 합성기(Web Audio)가 재생한다. 출처가 다른 곡도 같은 음색으로 통일되고, 곡당 수 KB다.
- 곡 출처 우선순위:
  1. 저작권이 만료된 르네상스·바로크 무곡·민요를 새로 편곡(우리 편곡은 CC BY-SA로 공개).
  2. CC0 / CC-BY 칩튠·MIDI(OpenGameArt 등), 출처 표기.
  3. CC-BY-SA 곡 — 편곡본도 CC BY-SA로 공개하는 조건으로 허용.
- **제외**: 비상업(NC)·변경 금지(ND) 라이선스. 이 프로젝트는 콘텐츠를 CC BY-SA로 공개해 누구나 상업적 이용·변형까지 할 수 있게 하는데, NC·ND 자료가 섞이면 게임 전체를 그 조건으로 재배포할 수 없게 된다.
- **금지**: 울티마 원곡과 그 편곡.

### 6.3 효과음
- CC0 효과음 묶음 + 코드로 생성하는 8비트 효과음(jsfxr 방식의 매개변수, 라이선스 문제 없음).

## 7. 기술 구조

### 7.1 모듈

```
src/core/        순수 규칙 (DOM·Canvas 접근 금지, Vitest로 직접 테스트)
  world/         지도·지형·이동 비용·낮밤·NPC 일과
  knowledge/     단서·수첩·추론 페이지(3칸 확정 규칙)·소문 지도
  dialogue/      키워드 대화 실행기
  virtue/        이해·행실 기록, 동료 신뢰·이탈 판정
  combat/        격자 턴제, 적 행동 예고, 밀어내기·설득·도주
  save/          상태 직렬화(버전 번호 + 마이그레이션)
src/render/      Canvas2D 타일·스프라이트 렌더러
src/audio/       칩 합성기 + 효과음
src/ui/          수첩·대화 칩·전투 HUD·메뉴 (DOM)
src/input/       키보드·마우스·터치 → 공통 "명령"
content/         지도(Tiled JSON), 대사·단서·추론(YAML), 문자열 표(ko/en), ip-denylist.yaml
assets/          그림·소리 파일 + LEDGER.md
scripts/         콘텐츠 검사기, 자산 장부 검사, 빌드 보조
```

### 7.2 데이터 흐름
`입력 → 명령 → core.step(state, command) → 새 state + 이벤트 목록 → render/ui/audio`

- core는 순수 함수 중심이며 화면을 모른다. 같은 명령 순서는 항상 같은 결과를 낸다(난수는 state 안의 시드로만).

### 7.3 콘텐츠 형식 (예시)

```yaml
# content/towns/kalas/npcs.yaml
- id: kalas.weaver
  name: 직조공 미라
  schedule: { day: kalas.market, night: kalas.home3 }
  topics:
    고백석:
      text: kalas.weaver.confession   # 문자열 표 키
      grants: [fact.kalas.daily-confession]
    순례자:
      requires: [fact.kalas.old-letter]
      text: kalas.weaver.pilgrim
      grants: [word.lantern]
```

```yaml
# content/towns/kalas/deduction.yaml
id: deduction.honesty
sentence: deduction.honesty.sentence   # "정직은 {1}을 {2}가 아니라 {3}로 쓰는 것"
slots:
  1: word.truth
  2: word.weapon
  3: word.lantern
unlocks: [ability.see-lies, crisis.kalas.option-b]
```

### 7.4 콘텐츠 검사기 (빌드 단계, 실패 시 빌드 중단)
- 대사·추론·위기가 가리키는 단서·단어·문자열 키·지도 출구가 실제로 존재하는가.
- 모든 추론 페이지의 정답 단어를 게임 안에서 얻을 수 있는가(획득 경로 존재).
- 금지 목록(§2.3)에 걸리는 문자열이 없는가.
- `assets/` 안의 모든 파일이 `LEDGER.md`에 출처·라이선스·작가와 함께 적혀 있는가. 장부에서 크레딧 화면을 자동 생성한다.

### 7.5 저장·배포
- 상태 전체를 하나의 JSON으로 직렬화(버전 번호 포함). 저장 슬롯(IndexedDB)과 Google Drive 선택 동기화는 기존 `ultima` 코드를 옮겨 쓰고, 저장 형식 부분만 새로 짠다.
- GitHub Pages 정적 배포 + PWA(오프라인 설치).

### 7.6 테스트
- core: TDD 단위 테스트(실패 테스트 먼저, RED 기록).
- 콘텐츠 검사기 자체의 단위 테스트(일부러 깨진 콘텐츠를 넣어 실패하는지).
- 시나리오 재생 테스트: "이 명령 순서로 플레이하면 칼라스 위기가 풀린다"를 헤드리스로 검사.
- e2e는 최소(부팅·저장 정도). 화면 확인은 사용자가 직접 한다(기존 작업 방식 유지).

### 8.1 M1 완료 기준 (사용자 판정의 기준점)
1. 칼라스 지도 1장, NPC 약 10명, 키워드 대화로 단서를 모을 수 있다.
2. 추론 페이지 1쪽: 빈칸 3개가 모두 맞을 때만 확정되고, 일부만 맞으면 확정도 힌트도 없다(단위 테스트 + 시나리오 테스트).
3. 위기 1개의 풀이 2갈래가 **둘 다** 끝까지 도달 가능하다(시나리오 테스트 2개).
4. 전투 1~2회: 하나는 악하지 않은 상대(밀어내기가 바람직), 하나는 악한 상대. 악하지 않은 상대를 죽이면 행실에 기록된다.
5. 동료 1명이 합류하고, 행실 조건에 따라 떠날 수 있다.
6. 음악 2곡(들판, 칼라스) + 효과음 몇 개가 칩 합성기로 재생된다.
7. 저장 → 불러오기 왕복 후 상태가 같다(단위 테스트).
8. PC 키보드·마우스와 모바일 터치로 끝까지 플레이 가능하다.
9. 사용자가 직접 플레이하고 **계속 / 방향 수정 / 중단**을 결정해 기록한다.

### 8.2 구현 계획의 범위
- 이 스펙은 게임 전체의 설계다. **첫 구현 계획은 M0 + M1만 다룬다.** M2 이후는 M1 판정이 나온 뒤 단계별로 따로 계획한다.
