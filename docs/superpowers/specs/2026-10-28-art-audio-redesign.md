## 0. 이해한 목표 (고쳐 주세요)
- 목표: 0.1.0의 "바둑알 + 칩 소리"를 **생성 픽셀 아트 + 녹음 음원**으로 바꾸되, 게임 규칙(core)과 대사·퍼즐 콘텐츠는 건드리지 않는다.
- 제약: 그림은 하루 보너스 5회로 천천히 늘어난다. 그래서 **새 그림이 있는 곳과 없는 곳이 한동안 섞인다.** 설계는 "한 번에 다 바꾸기"가 아니라 "엔진을 먼저 바꾸고, 그림은 들어오는 대로 채우기"여야 한다. 소리는 CC0/CC-BY/CC-BY-SA만 배포한다.
- 성공 기준: ① 새 엔진 위에서 8개 마을이 모두 돌아간다(그림이 옛것이어도). ② 칼라스 한 판이 새 그림·소리로 끝까지 플레이된다. ③ 배포 용량·라이선스 검사가 통과한다. ④ 화면·소리는 사람이 보고 듣고 판정한다(AGENTS.md §9.1).

## 2. 화면 규격
- **칸(TILE) = 32px.** 캐릭터는 48×48 캔버스(발이 칸 아래 중앙, 머리가 위로 16px, 좌우 8px 겹침). 옛 16px 시트는 `tile: 16`으로 표시하고 그릴 때 2배(최근접).
- **시야와 배율**(결정 1, 추천): 가로 화면 **11×7칸 × 3배**(칸 96px). 지금 15×11 ×2에서는 캐릭터가 화면 높이의 10%뿐이다. 칸 수는 고정이 아니라 "정수 배율을 먼저 고르고 그 배율에서 들어가는 칸 수"로 정한다: `scale = clamp(floor(canvasH / (7×32)), 2, 4)`, 가로 칸 수 = `floor(canvasW / (32×scale))`(최대 15, 최소 7), 세로 7. 세로 화면은 7×9. 실험실(`/lab/`)에서 이미 비교할 수 있다.
- 지도가 시야보다 작으면 가운데 정렬(지금 규칙 유지). 터치 길찾기는 `screenToTile` 역변환을 그대로 쓴다.
- 전투 격자도 같은 그리기 경로를 쓴다(땅 층 + 유닛 층).

## 3. 렌더링 구조 (`src/render/`)
순서: **① 땅 층 → ② 물건·캐릭터 층(발 y 기준 정렬) → ③ 전투 겹침(예고 화살표·테두리) → ④ 화면 효과**. 2D 캔버스 하나에 그리고 DOM UI는 그 위에 얹는다(0.1.0과 같다).

### 3.1 데이터 모양 (콘텐츠 변경은 하위 호환)
- `content/tiles.yaml` 글자 한 개의 정의를 확장한다. 옛 `sprite: [sheet, index]`는 그대로 허용(옛 그림 호환).
  - 새 글자: `{ ground: grass | path | water | stone | floor, walk, object?: <물건 id> }`.
- **물건**(`content/objects.yaml`, 새 파일): `{ image, footprint: [w,h], anchor: bottom-left, blocks: true|false, door?: [dx,dy] }`. 집·나무·열석·고백석 등. 한 물건이 여러 칸을 차지해도 지도 글자는 **물건이 서는 기준 칸에 한 글자**로 적는다.
- 지도(`maps.yaml`)에 `objects: [{ id, at: [x,y] }]`를 추가할 수 있다. 컴파일러가 물건 발자국을 **막힌 칸으로 합쳐** 기존 걷기 판정용 `rows`를 만든다 → **core의 이동·길찾기 코드는 바뀌지 않는다.** 땅 격자(`ground`)는 별도로 렌더에 넘긴다.
- NPC·플레이어·크리처의 `sprite`는 `[sheet,index]`(옛) 또는 `char.<이름>`(새)을 모두 받는다.

### 3.2 자동 타일(Wang)
- 방식: **듀얼 그리드.** 논리 칸(땅 종류 하나)과 그리는 타일을 반 칸 엇갈리게 놓는다. 그리는 타일 하나는 둘러싼 네 논리 칸을 모서리(NW·NE·SW·SE)로 삼아 16개 중 하나를 고른다. 모호함이 없고 지도 글자 그대로 쓸 수 있다.
- 기본 땅은 풀. 풀↔흙길, 풀↔물처럼 **짝 시트 하나가 두 종류만 잇는다.** 풀 아닌 종류는 순서(길 → 물 → 돌바닥)대로 풀 위에 덮어 그린다.
- 규칙(콘텐츠 검사 추가): 풀 아닌 두 종류(길과 물 등)는 **서로 맞닿을 수 없다**(다리·성문 같은 물건이 사이에 있을 때만 예외). 시트가 없는 조합은 빌드 오류.
- 모서리→시트 칸 표는 PixelLab `metadata.json`의 `corners`·`original_position`에서 스크립트(`scripts/assets/make-autotile.mjs`)가 한 번 만들어 `autotile.json`으로 저장소에 둔다. 순수 함수 `pickWang(corners) → {col,row}`는 단위 테스트한다.
- 던전(서고)은 바닥 `floor`와 벽 물건으로 구성(벽은 3.1의 막는 물건, 별도 Wang 필요 시 3차에).

### 3.3 물건·캐릭터 정렬과 걷기 애니메이션
- 정렬 키 = 발이 서는 칸의 y(같으면 물건 먼저, 그 뒤 NPC, 마지막에 플레이어). 나무 뒤로 걸으면 가려진다.
- **걷기는 순수 표현이다.** core는 칸 단위로 순간 이동한다. 렌더 쪽 `RenderMotion`이 `moved`·`mapChanged` 이벤트에서 "이전 칸→새 칸 130ms 보간 + 걷기 프레임"을 만든다(core 상태·저장에 들어가지 않음). 입력은 이동 중에도 받는다(보간은 새 입력이 오면 즉시 끝점으로 점프).
- 방향: 플레이어는 `state.player.facing`. NPC는 기본 남쪽, 대화 중에는 플레이어를 향한다.
- 걷기 그림이 없는 인물은 **대기 4방향 + 위아래 2px 흔들림**으로 대신한다(`art-kalas-cast.md` 방침).
- NPC는 일과표(시간)로 위치가 바뀌므로 보간하지 않고 즉시 이동한다.

### 3.4 자산 불러오기
- 개별 PNG를 Vite `import.meta.glob`으로 URL화하고 **지도에 필요한 것만 그 지도에 들어갈 때 불러온다**(마을 이동 시 로딩 표시 없이 한 프레임 미리 불러오기). 아틀라스 합치기는 하지 않는다(YAGNI, 파일 수백 개 규모에서 필요 없음).
- 마을색 변형은 **미리 만든 파일**로 저장소에 둔다(`scripts/visual/recolor.mjs`, 결정적·검토 가능). 실행 중 색 변환은 하지 않는다.

## 4. 소리 (`src/audio/`)
### 4.1 제거와 교체
- 칩 합성기(`synth.ts`·`score.ts`·`sfx.ts`), `content/music/*.yaml` 악보, 관련 테스트·검사를 **새 엔진이 들어오고 나서** 제거한다(그전까지 폴백).
- 새 파일 `content/audio.yaml`: 소리 id → 파일 매핑 한 곳. 코어가 내는 `sfx { name }`·`music { track }` 이벤트의 이름은 그대로 두고, 이 표만 바꾼다.

### 4.2 효과음
- Web Audio `AudioBuffer`로 첫 사용자 입력 때 디코드(OGG 14개 합 ≈ 0.5MB). 같은 소리 동시 재생은 최대 3개.
- 발걸음은 **밟은 땅**으로 고른다: 풀·길 `footstep`, 돌 `footstep_stone`, 다리·나무바닥 `footstep_wood`. 걸을 때마다 ±5% 재생 속도 변화로 단조로움을 줄인다.
- 이름 매핑: `step→footstep*`, `bump`, `learn→clue`, `confirm`, `hit`, `push`, 메뉴 `click`, 수첩 `page`, 틀림 `wrong`, 문 `door`, 순간이동 `teleport`, 보상 `coins`.
- **소리 없는 14개 상황**(맵 이동·전투 시작·방어·설득·도주·승리·패배·동료 합류/이탈·열석 열림·능력·위기·경전 쓰기·에필로그): 후보가 `assets-private/preview/`에 있고 사용자 선택 전이다. 선택 전에는 **무음으로 두고**(오류 아님), 선택하면 `audio.yaml`에 한 줄 추가로 끝난다.

### 4.3 배경 음악
- 12곡(`assets/audio/bgm/*.ogg`, 106초 루프, 합 11MB). **지도에 들어갈 때 그 곡만** `fetch → decodeAudioData`, `AudioBufferSourceNode.loop = true`(끊김 없는 반복). 곡이 바뀌면 1.5초 교차 페이드, 이전 곡 버퍼 해제.
- 디코드 후 메모리는 곡당 약 37MB(스테레오 44.1k). 동시에 최대 2곡(페이드 중)만 쥔다. 모바일이 부담이면 모노 변환을 후속으로 검토(확인 필요).
- 자동재생 정책: 첫 입력 전에는 재생하지 않고 "지금 곡"만 기억(0.1.0과 동일).
- 슬롯 불일치: 지도 `music.overworld`에 대응하는 곡이 없고(`ending`은 코어의 곡 이름이 아님). 추천: 대륙은 `field` 곡을 쓰고, `ending`은 `epilogue` 이벤트에 연결한다. → `audio.yaml`에서 해결, 코어 변경 없음.
- 크레딧: `credits.json`(CC-BY 표기 필수)을 크레딧 패널이 읽어 곡명·작가·라이선스·원문 URL을 보여 준다. 표기가 없으면 `audit:dist`가 실패한다.
- 음량: 효과음·음악 별도 슬라이더(설정 패널), 기본 음악 0.5·효과음 0.8, 마지막 값은 `localStorage`(저장 실패해도 동작).

## 5. 배포 용량과 라이선스 검사
- 지금 예산 5MiB는 음악 11MB로 이미 넘는다. **결정 2**(추천): 예산을 범주별로 나눈다. 코드+콘텐츠 3MiB · 그림 6MiB · 소리 16MiB(합 25MiB). 처음 접속에 쓰는 양(코드+현재 지도의 그림+효과음)은 **5MiB 이하**를 별도 기준으로 둔다(`audit:dist`가 지도별 첫 로딩 합계를 계산). 음악은 지도 진입 때 지연 로딩이라 첫 로딩에 들지 않는다.
- `audit:dist`에 추가: ① `assets-private/`·`lab/`에서 온 파일이 dist에 있으면 실패 ② `assets/audio/**`·`assets/sprites/**` 파일마다 `assets/LEDGER.md`에 행과 허용 라이선스가 있어야 함 ③ `credits.json`에 있는 곡 전부가 크레딧 UI에 노출될 수 있어야 함. 비상업 전용(ElevenLabs 등)은 어떤 경우에도 dist에 들어가지 않는다(자산 장부 등급으로 막는다).
- 새 그림·소리마다 장부에 도구·약관 URL·생성 날짜를 적고, 프롬프트·설정은 `assets/generated/prompts/`에 둔다(AGENTS.md §3 그대로).

## 6. 구현 순서(계획 P의 뼈대)
1. **I-1 엔진, 그림 그대로**: TILE 32 + 옛 시트 2배 확대, 가변 시야·배율, 카메라, 정렬 층, `RenderMotion`(보간·방향), 새 소리 엔진(매핑·발걸음·음악 교차 페이드). 8개 마을이 옛 그림으로 새 엔진에서 돈다. 칩 합성기 제거.
2. **I-2 칼라스 땅**: 듀얼 그리드 Wang, 풀↔흙길·풀↔물·다리, 물건 층, 칼라스 3장 이전(맵 그림 약 15회 필요).
3. **I-3 칼라스 인물**: 기존 11명+새 인물 기본형, 걷기.
4. **I-4 서고·전투**, 5. **마을 7곳 순차**, 6. **대륙·UI·초상화(선택)**.
각 단계의 끝에서 에이전트가 스크린샷·영상을 직접 열어 확인하고 사용자가 보고 듣고 판정한다. e2e는 돌리지 않는다.

## 9. 알려진 위험
- 듀얼 그리드는 풀 아닌 두 종류가 닿는 곳에서 모호하다 → 3.2의 검사 규칙으로 금지(필요하면 전환 시트를 추가 생성).
- 새/옛 그림 혼합 동안 같은 화면에서 해상도가 다르다(옛 그림 2배 확대). 칼라스 완성 전에는 마을마다 화풍이 다름을 사용자가 감안해야 한다.
- 곡당 37MB 디코드 메모리(모바일 확인 필요).
- 생성 횟수 부족으로 맵 그림이 늦어지면 I-2가 지연된다. I-1은 그림과 무관하다.
