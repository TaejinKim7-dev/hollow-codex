## 0. 방향 전환 (2026-10-07 사용자 결정)

사용자가 0.1.0 배포본을 보고 그래픽과 소리를 **게임으로 볼 수 없는 수준**이라고 판정했다. 이 판정이 M1 플레이 판정을 대신한다: **"방향 수정"**.

| 항목 | 0.1.0 (폐기) | 새 방향 (확정) |
|---|---|---|
| 그래픽 | Kenney Tiny Town/Dungeon 16×16, 칸마다 그림 하나 | **픽셀 아트 생성 MCP로 만든 고해상도 픽셀 아트**(2026-10-18 사용자 결정: 직접 그리지 않고 생성 도구를 붙인다). 32×32 이상, 타일·마을·실내·던전·마을 사람·몬스터·플레이어가 **한 화풍**, 4방향 걷기 애니메이션. 공개 묶음은 생성으로 못 채우는 빈 곳에만 쓴다 |
| 소리 | 사각파·삼각파 칩 합성기(단음) | **실제 악기로 녹음된 공개 라이선스 음원**(중세·판타지). 효과음도 녹음 음원 |
| 확인 | 아무도 화면을 보지 않고 "출시 가능" 보고 | 화면·소리 변경은 **스크린샷과 사람 확인 없이 완료 금지** (AGENTS.md §9) |

0.1.0에서 확인된 그래픽 결함(새 방향에서 반드시 없어야 함):
- 투명 배경 그림(나무·덤불·돌) 아래에 땅을 깔지 않아 **검은 사각형**이 보였다. 원인: `src/render/canvas.ts`가 화면을 검게 칠한 뒤 칸마다 그림 하나만 그린다. 땅 층과 물건 층이 없다.
- 타일 번호를 그림을 보지 않고 추정해 열석이 동전처럼, 고백석이 상자처럼 보였다(`content/tiles.yaml`).

유지하는 것: 게임 구조(대화로 단서를 모으는 탐험, 8마을, 3칸 추론, 위기, 격자 전투, 빈 경전 엔딩), 순수 core, 콘텐츠 YAML, 저장, 테스트·게이트, 원작 IP 경계(spec §2).

## 1. 원칙

1. **보고 들은 것만 완료다.** 그래픽·소리는 스크린샷·녹음 확인과 사용자 판정이 있어야 끝난다.
2. **자산은 라이선스 원문을 읽고 고른다.** 기억이나 요약에 의존하지 않는다. 저장소가 공개이므로 "원본 파일을 공개 저장소에 올려도 되는가"를 반드시 확인한다.
3. **고치기 전에 재현한다.** 실패하는 테스트나 실제 콘텐츠 탐침이 먼저다.
4. **구현자와 검토자를 나눈다.** 마일스톤마다 독립 전체 검토를 돌린다.
5. **한계는 숨기지 않는다.** README와 `docs/handoff.md`에 사실대로 적는다.

## 2. 로드맵 (0.2.0 — 그래픽·소리 재정비)

순서대로 한다. 각 단계의 종료 조건을 채우고 사용자 확인이 필요한 곳(🧑)에서는 멈춘다.

### R — 자산 방향 확정 (게임 코드 변경 없음)
- **R-1 픽셀 아트 생성 시범** → 결과 `docs/research/art-generation-trial.md`, 이미지 `docs/screenshots/`
  - 도구(2026-10-18 확인):
    - **PixelLab MCP (1순위)** — 공식 원격 MCP `https://api.pixellab.ai/mcp`(HTTP, `Authorization: Bearer <토큰>`), 설정 안내 https://www.pixellab.ai/vibe-coding, 저장소 https://github.com/pixellab-code/pixellab-mcp. 도구: `create_character`(4/8방향), `animate_character`(걷기 등), `create_tileset`(Wang 타일셋), `create_isometric_tile`. 이용 약관: "You retain ownership of any content you create using PixelLab." / "You are free to use, modify, and distribute the outputs from our tools for any purpose, except for training other models without our explicit permission." (https://www.pixellab.ai/termsofservice)
    - **Retro Diffusion MCP (비교 후보)** — 원격 MCP `https://mcp.retrodiffusion.ai/mcp`(Bearer, 키 `rdpk-…`), 90여 가지 화풍, 4방향 걷기, Wang/blob 타일셋. **이용 약관 원문은 아직 확인 못 함**(제작자 발언 "you own the images"만 확인) — 쓰기 전에 약관 원문 확인 필수.
  - 🧑 사용자가 계정을 만들고 API 토큰을 발급해 MCP를 붙인다(토큰은 저장소에 넣지 않는다, AGENTS.md §2). 가격·크레딧 한도도 이때 확인.
  - 시범 세트(두 도구에 같은 프롬프트): 플레이어 4방향 걷기, 마을 사람 2명, 늑대, 들판 Wang 타일셋(풀↔흙길, 풀↔물), 다리, 나무, 열석, 칼라스 집 1채, 고백석. 화풍 고정 방법(참조 이미지, 팔레트, 크기)을 함께 시험한다.
  - 기록: 도구·모델·프롬프트·크기·날짜·비용(크레딧)·결과 이미지. 생성 결과를 게임 화면 크기로 붙인 목업 스크린샷 1장.
  - 프롬프트 규칙: 원작 게임 이름·캐릭터·화면을 언급하거나 흉내 내라고 쓰지 않는다(spec §2). 특정 작가·작품 화풍 지정도 하지 않는다.
  - 종료 조건: 🧑 사용자가 목업을 보고 도구와 화풍을 고른다.
- **R-2 음원 조사** → 결과 `docs/research/audio-assets.md`
  - 필요: 루프 곡 약 12개(들판, 8마을 분위기별, 서고, 전투, 엔딩) + 효과음(발걸음, 부딪힘, 클릭, 책장, 발견, 확정, 타격, 밀기, 문, 순간이동).
  - 후보 예: Kevin MacLeod(incompetech, CC-BY 4.0), Musopen의 CC0 녹음, OpenGameArt CC0/CC-BY 곡, Freesound CC0, Kenney 오디오(CC0). 공유 저작물 곡이라도 **녹음 자체**가 CC0/PD여야 한다.
  - 결론: 추천 세트, 빈 곳, 크레딧 문구, 용량 추정(OGG 96–128kbps)과 배포 예산(지금 5 MiB) 처리안(예산 상향 또는 지역별 지연 로딩).
- 종료 조건: 두 문서가 저장소에 있고, 라이선스 인용이 실제 페이지에서 확인됐다.
- 🧑 사용자가 그래픽 도구·화풍(R-1)과 음원 세트(R-2)를 고른다. 유료 크레딧·묶음 구매 여부도 이때 정한다.

### S — 새 설계 문서
- 사용자 선택을 반영해 `docs/superpowers/specs/<날짜>-art-audio-redesign.md`를 쓴다. spec §5(그래픽)·§6(음악)·§7.1(render/audio 구조)을 대체하는 부분을 명시한다.
- 필수 내용: 타일 크기와 화면 배율, **땅 층 + 물건 층 + 캐릭터 층** 렌더링, Wang 타일셋을 지도에 까는 규칙(자동 타일), 걷기 애니메이션, 생성 자산 파이프라인(프롬프트·참조 이미지·팔레트를 저장소에 남겨 다시 만들 수 있게), 자산 장부 기록 방식(생성 도구·약관), 음원 형식·로딩·용량 예산, 기존 칩 합성기 제거 여부.
- 🧑 사용자가 설계 문서를 승인한다.

### P — 구현 계획
- 승인된 설계로 `docs/superpowers/plans/<날짜>-art-audio-redesign.md`를 쓴다(Task별 파일·테스트·명령).
- 🧑 사용자가 계획을 확인한다.

### I — 구현
- 시각 확인 단계 포함: Task마다 Playwright로 들판·칼라스·서고·전투 화면 스크린샷을 찍어 에이전트가 직접 보고, 결과 이미지를 `docs/screenshots/`에 남긴다.
- 🧑 사용자가 배포본을 보고 듣고 판정한다(계속 / 방향 수정 / 중단).
