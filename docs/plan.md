# 빈 경전 — 방향과 로드맵 (plan.md)

최종 수정: 2026-10-18 · 기준 main `b17ee6d` (0.1.0)
이 문서는 "무엇을, 어떤 순서로, 왜"만 정한다. 지금 상태와 다음 할 일은 `docs/status.md`, 작업 기록은 `docs/handoff.md`.

## 0. 방향 전환 (2026-10-07 사용자 결정)

사용자가 0.1.0 배포본을 보고 그래픽과 소리를 **게임으로 볼 수 없는 수준**이라고 판정했다. 이 판정이 M1 플레이 판정을 대신한다: **"방향 수정"**.

| 항목 | 0.1.0 (폐기) | 새 방향 (확정) |
|---|---|---|
| 그래픽 | Kenney Tiny Town/Dungeon 16×16, 칸마다 그림 하나 | **외부 공개 사용이 가능한 고해상도 픽셀 아트**(32×32 이상 또는 그만큼 다듬어진 묶음). 타일·마을·실내·던전·마을 사람·몬스터·플레이어가 **한 화풍**, 4방향 걷기 애니메이션 |
| 소리 | 사각파·삼각파 칩 합성기(단음) | **실제 악기로 녹음된 공개 라이선스 음원**(중세·판타지). 효과음도 녹음 음원 |
| 확인 | 아무도 화면을 보지 않고 "출시 가능" 보고 | 화면·소리 변경은 **스크린샷과 사람 확인 없이 완료 금지** (AGENTS.md §9) |

0.1.0에서 확인된 그래픽 결함(새 방향에서 반드시 없어야 함):
- 투명 배경 그림(나무·덤불·돌) 아래에 땅을 깔지 않아 **검은 사각형**이 보였다. 원인: `src/render/canvas.ts`가 화면을 검게 칠한 뒤 칸마다 그림 하나만 그린다. 땅 층과 물건 층이 없다.
- 타일 번호를 그림을 보지 않고 추정해 열석이 동전처럼, 고백석이 상자처럼 보였다(`content/tiles.yaml`).

유지하는 것: 게임 구조(대화로 단서를 모으는 탐험, 8마을, 3칸 추론, 위기, 격자 전투, 빈 경전 엔딩), 순수 core, 콘텐츠 YAML, 저장, 테스트·게이트, 원작 IP 경계(spec §2).

## 1. 원칙

1. **보고 들은 것만 완료다.** 그래픽·소리는 스크린샷·녹음 확인과 사용자 판정이 있어야 끝난다.
2. **자산은 라이선스 원문을 읽고 고른다.** 기억이나 요약에 의존하지 않는다. 저장소가 공개이므로 "원본 파일을 공개 저장소에 올려도 되는가"를 반드시 확인한다.
3. **고치기 전에 재현한다.** 실패하는 테스트나 실제 콘텐츠 탐침이 먼저다.
4. **구현자와 검토자를 나눈다.** 마일스톤마다 독립 전체 검토를 돌린다.
5. **한계는 숨기지 않는다.** README와 `docs/handoff.md`에 사실대로 적는다.

## 2. 로드맵 (0.2.0 — 그래픽·소리 재정비)

순서대로 한다. 각 단계의 종료 조건을 채우고 사용자 확인이 필요한 곳(🧑)에서는 멈춘다.

### R — 자산 조사 (코드 변경 없음)
- **R-1 그래픽 자산 조사** → 결과 `docs/research/art-assets.md`
  - 대상: 위 "새 방향" 기준. 후보 예: LPC(Liberated Pixel Cup) 타일·캐릭터 생성기, Ninja Adventure(CC0), Mana Seed, Cainos, Pixel Frog, LimeZu, Sprout Lands, Mystic Woods, Time Fantasy, ArMM1998 등. 목록은 출발점일 뿐이고 직접 더 찾는다.
  - 각 후보: 이름 · URL · 작가 · 라이선스(핵심 문장 인용) · **공개 저장소 재배포 가능 여부(조항 인용)** · 타일 크기 · 범위(지형/마을/실내/던전/캐릭터/몬스터/애니메이션) · 가격 · 화풍.
  - 결론: 모든 요구를 한 화풍으로 덮는 **추천 조합 1개**, 남는 빈 곳, 크레딧 문구.
- **R-2 음원 조사** → 결과 `docs/research/audio-assets.md`
  - 필요: 루프 곡 약 12개(들판, 8마을 분위기별, 서고, 전투, 엔딩) + 효과음(발걸음, 부딪힘, 클릭, 책장, 발견, 확정, 타격, 밀기, 문, 순간이동).
  - 후보 예: Kevin MacLeod(incompetech, CC-BY 4.0), Musopen의 CC0 녹음, OpenGameArt CC0/CC-BY 곡, Freesound CC0, Kenney 오디오(CC0). 공유 저작물 곡이라도 **녹음 자체**가 CC0/PD여야 한다.
  - 결론: 추천 세트, 빈 곳, 크레딧 문구, 용량 추정(OGG 96–128kbps)과 배포 예산(지금 5 MiB) 처리안(예산 상향 또는 지역별 지연 로딩).
- 종료 조건: 두 문서가 저장소에 있고, 라이선스 인용이 실제 페이지에서 확인됐다.
- 🧑 사용자가 추천 조합을 고른다. 유료 묶음을 살지, 공개 저장소에 원본을 못 올리는 라이선스를 받아들일지도 이때 정한다.

### S — 새 설계 문서
- 사용자 선택을 반영해 `docs/superpowers/specs/<날짜>-art-audio-redesign.md`를 쓴다. spec §5(그래픽)·§6(음악)·§7.1(render/audio 구조)을 대체하는 부분을 명시한다.
- 필수 내용: 타일 크기와 화면 배율, **땅 층 + 물건 층 + 캐릭터 층** 렌더링, 걷기 애니메이션, 자산 장부·라이선스 처리(재배포 불가 자산이면 저장소 밖 보관 + 빌드 때 가져오기 등), 음원 형식·로딩·용량 예산, 기존 칩 합성기 제거 여부.
- 🧑 사용자가 설계 문서를 승인한다.

### P — 구현 계획
- 승인된 설계로 `docs/superpowers/plans/<날짜>-art-audio-redesign.md`를 쓴다(Task별 파일·테스트·명령).
- 🧑 사용자가 계획을 확인한다.

### I — 구현
- 시각 확인 단계 포함: Task마다 Playwright로 들판·칼라스·서고·전투 화면 스크린샷을 찍어 에이전트가 직접 보고, 결과 이미지를 `docs/screenshots/`에 남긴다.
- 🧑 사용자가 배포본을 보고 듣고 판정한다(계속 / 방향 수정 / 중단).

### 그 뒤 (0.2.0 판정 뒤에 범위를 다시 정함)
0.1.0에서 넘어온 스펙 차이: 열석 고리 단서 대화(지금 순간이동이 실제로 안 열림) · 에필로그에 위기 풀이 반영 · 틀린 경전 단어 안내 · 능력 6개와 능력 화면 · 동료 7명. 공개 준비: 정식 상표 확인, 접근성 점검, 라이선스 최종 점검. npm audit 개발 도구 취약점 6건.
